# Hospital Management System

A Python-based Hospital Patient Management System designed to manage patient records using CRUD operations, PostgreSQL database integration, and automated testing.

This project was developed in two versions to demonstrate the transition from file-based data storage to a relational database architecture.

## 1. Project Overview

The Hospital Management System is a command-line application that allows users to add, view, search, update, and delete patient records.

The project focuses on Python programming, object-oriented design, database connectivity, SQL operations, input validation, exception handling, and software testing.

## 3. Version 1 — JSON-Based System

The first version uses JSON files to store patient information.

**Features:**
- Add new patients
- View all patients
- Search patients by ID
- Update patient information
- Delete patient records
- Validate patient information
- Handle invalid inputs
- Persist records using JSON

**Data Storage:** `data/patients.json`

This version demonstrates fundamental Python programming, file handling, and CRUD functionality.

## 4. Version 2 — PostgreSQL-Based System

Version 2 replaces JSON-based persistence with PostgreSQL.

**Features:**
- PostgreSQL database connectivity
- SQL-based CRUD operations
- Auto-generated patient IDs
- Parameterized SQL queries
- Database transaction management
- Exception handling
- Environment-based database configuration
- Automated repository testing

### Application Architecture

```text
Hospital Management System
        |
        v
      main.py
        |
        v
     patient.py
        |
        v
patient_repository.py
        |
        v
     database.py
        |
        v
     PostgreSQL
```

**Component Responsibilities**

- `main.py` — Handles the command-line menu and user interactions.
- `patient.py` — Defines the Patient model and its attributes.
- `patient_repository.py` — Implements SQL-based CRUD operations.
- `database.py` — Establishes PostgreSQL connections using environment variables.
- `tests/test_patient_repository.py` — Contains automated repository tests.

## 5. Database Design

The application uses a `patients` table.

| Column | Description |
|---|---|
| patient_id | Unique patient identifier |
| name | Patient name |
| age | Patient age |
| gender | Patient gender |
| condition | Patient medical condition |

The `patient_id` is generated by PostgreSQL when a new record is inserted.

## 6. Installation and Setup

### Clone the repository

```bash
git clone <repository-url>
cd <repository-folder>
```

### Create a virtual environment

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### Install dependencies

```bash
python -m pip install -r requirements.txt
```

### Configure PostgreSQL

Create a PostgreSQL database named `hospital_management` and create the required `patients` table using the schema configured for the application.

Copy `.env.example` to `.env` and provide your local database credentials.

```env
DB_HOST=localhost
DB_PORT=5432
DB_NAME=hospital_management
DB_USER=your_username
DB_PASSWORD=your_password
```

Do not commit `.env` or real patient information to GitHub.

### Run the application

```bash
python main.py
```

## 8. Automated Testing

Version 2 includes automated repository tests using Python's `unittest` framework and `pytest`.

The tests use mocked PostgreSQL connections and cursors to validate repository behavior without modifying the real database.

**Test coverage includes:**
- Successful patient insertion
- Patient retrieval
- Retrieving all patients
- Updating patient records
- Deleting patient records
- Patient-not-found scenarios
- Database exception handling for CRUD operations

### Run tests

```bash
python -m pytest tests/ -v
```

**Latest verified test result: 13 passed.**

These tests validate mocked repository behavior. They do not replace integration testing against a real PostgreSQL database.

## 9. Security and Error Handling

The project implements several foundational practices:

- Database credentials loaded from environment variables
- Parameterized SQL queries to reduce SQL injection risks
- Exception handling for database operations
- Validation of patient input
- Confirmation before patient deletion
- Git exclusions for local secrets and patient data

This is a learning project and is not intended for storing real patient health information or production clinical use.
